# Steam Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** A documented, tested Steam plugin with equally capable profiles and household pages.

**Architecture:** A Python plugin using FiestaBoard's named instances. A small Steam client normalizes external failures and caches endpoint responses; plugin code composes data and board-aware layouts. Real core and browser integration tests use fixture HTTP responses.

**Tech Stack:** Python 3.12+, requests, pytest, FiestaBoard PluginBase, Playwright.

**Spec:** ../specs/2026-10-29-steam-design.md

## Global Constraints

- No shared developer secret, OAuth or core product changes.
- Same fields for every selected Steam profile; actual Steam privacy governs access.
- Presence >=30s, default 60s; stats 5m, friend list 15m, schemas and vanity 24h.
- Never log keys or treat unavailable stats/counts as zero.
- Templates support named instances and every board geometry.

## Review Focus

- Profile edits and instance caches must never mix users.
- Private/omitted data must remain unknown, including hidden playtime.
- Malformed Steam payloads and partial friend batches must produce honest errors.
- User-provided names cannot inject FiestaBoard markup.
- Settings and example variables must work in the real editor, not just unit tests.
